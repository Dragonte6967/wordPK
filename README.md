# Word PK

基于 Vue 3、Node.js 和 Socket.IO 的多人实时词汇对战网页。玩家通过房间码加入同一场比赛，支持平衡组队、不平衡组队和个人马拉松赛制。

![组队房间](docs/screenshots/02-team-room.png)

## 功能

- 最多 5v5 组队对战，平衡模式要求双方人数相等。
- 不平衡模式允许双方人数不同，团队成绩按队内平均分计算。
- 最多 10 人参加的马拉松赛，率先超过 4219 分获胜。
- 房主可设置词库、题目数量、每题时间和是否允许人数不平衡。
- 提供四六级、考研、中考、高考、常用和“我想挑战一下我的软肋”六套词库。
- 常用词库已清理明显的人名、地名、姓氏、重复变形、缩写、单位及网络用语；清理脚本为 `scripts/clean-common-dictionary.mjs` 和 `scripts/clean-common-abbreviations.mjs`（默认仅预览）。清理报告与恢复归档仅保存在本地 `docs/dictionary-cleanup/`，不纳入版本控制。
- 房间码邀请、队伍切换、队名修改、准备状态及原房间再来一局。
- 服务器统一控制题目、倒计时、计分和结算。
- 测试分支支持 PeerJS 低延时模式：房主浏览器承担出题、计时、判分、准备与队伍规则、结算等裁判工作。
- 使用低延迟样本过滤的双向时间校准，并在切题时重新同步。
- 逐题个人结算、队伍结算及离线玩家成绩保留。
- 记录房间创建、开赛、结赛和销毁日志。
- 提供密码保护的管理后台，查看实时房间、比分及服务器监控图表。
- 支持桌面端和移动端响应式布局。

## 比赛规则

- 答对：按提交时的剩余时间百分比加分。
- 答错：按相同的剩余时间百分比扣分。
- 未作答：正分变为原分的 90%；负分额外增加 10% 惩罚。
- 所有赛制开赛前均有服务器同步的 3 秒倒计时。
- 马拉松连续 10 题无人作答时，服务器自动销毁房间。

## 技术栈

- Vue 3 + Vite
- Node.js + Express
- Socket.IO（仅使用 WebSocket 传输）
- PeerJS + 自托管 PeerServer（可选的房主裁判模式）

## 运行要求

- Node.js 20 或更高版本
- pnpm（推荐）或 npm
- TCP 端口 `3000` 和 `3001` 可访问

## 安装与运行

```powershell
pnpm install
pnpm run build
pnpm start
```

然后访问：

```text
http://服务器地址:3000
```

- `3000`：网页和运行时配置接口。
- `3001`：Socket.IO 游戏服务及 `/peerjs` 下的 PeerJS 信令。

管理员后台地址为 `http://服务器地址:3000/admin`。首次启动时，服务器控制台会显示一次性初始化码；首次打开后台时输入该码并设置至少 12 位的管理员密码，之后使用密码登录。后台每 5 秒刷新房间与负载数据，图表保留当前服务进程最近 30 分钟的采样。密码以加盐哈希形式保存在 `logs/admin-auth.json`；请妥善保留该文件，删除后后台会重新进入首次设置流程。

后台可设置首页滚动公告及开始、结束时间；公告仅在设定时间内显示于首页页眉下方，不会出现在房间或答题页面。设置持久化于 `logs/banner.json`。

服务默认监听所有网络接口。在局域网或公网部署时，需要在防火墙和安全组中放行上述两个 TCP 端口。

## 低延时模式（测试分支）

在 `codex/peerjs-low-latency` 分支中，房主可在房间设置内点击“尝试升级至低延时模式”。所有当前队员与房主通过 PeerJS 建立可靠的数据通道后才完成升级，升级后需要队员重新准备。连接失败或 25 秒内未完成升级时保留服务器模式，房主也可在大厅手动切回服务器模式。新玩家加入或大厅成员离开时会回到服务器模式，可再次尝试升级。

升级成功后，房主按所选词库下载裁判数据并在浏览器中出题；普通赛预发全部题目和选项，马拉松按 10 题一批预发，第 5 题经过 3% 时间时补下一批。队员不会收到整套裁判词库或未提交题目的答案。准备、设置、换队、改名、开赛、提交答案、判分、未答惩罚、切题、马拉松胜负判定及再来一局均由房主浏览器处理。队伍成绩仍按原规则取总分或平均分。

服务器仍用于房间码和成员登记、PeerJS 信令、连通状态管理，以及接收房主在房间变化和切题时上报的比分供日志和后台查看；它不再重新判题。马拉松连续 10 题无人作答由房主判定，再请求服务器注销房间。题目和答案直接经队员与房主的数据通道交换，不经过 Socket.IO 游戏服务。

房主需要保持网页在前台，浏览器休眠、刷新或离线会中断该模式；对局中房主掉线会关闭房间，不会自动迁移裁判。队员掉线后其成绩保留。该模式信任房主，房主可在自己的浏览器中接触题库及答案，适合熟人测试，不具备防房主作弊能力。

公网建议使用 HTTPS。如果通过 443 反向代理游戏服务，除了 `/socket.io/`，还需要把 `/peerjs/` 的 HTTP 和 WebSocket 请求一并转发至 `3001`。信令不使用 PeerJS 公共云。默认使用 Google STUN；某些 NAT 无法直接打洞，可通过 `PEER_ICE_SERVERS` 提供自己的 STUN/TURN 配置（JSON 数组）。TURN 会转发连接流量，但不会承担裁判工作；无法建立连接时继续使用服务器模式。PeerJS 的部署要求可参考[官方说明](https://peerjs.com/server/getting-started)。

## 开发

分别启动前端开发服务器和游戏服务器：

```powershell
pnpm run dev
pnpm run server
```

生产构建：

```powershell
pnpm run build
```

联机冒烟测试：

```powershell
node scripts/smoke.mjs
node scripts/admin-smoke.mjs
```

测试会临时使用 `3099` 和 `3100` 端口。

## 环境变量

| 变量 | 默认值 | 说明 |
| --- | ---: | --- |
| `PORT` | `3000` | 网页服务端口 |
| `SOCKET_PORT` | `3001` | WebSocket 游戏服务端口 |
| `START_COUNTDOWN_MS` | `3000` | 开赛倒计时毫秒数 |
| `LOG_FILE` | `logs/wordpk.log` | JSONL 日志文件路径 |
| `ADMIN_AUTH_FILE` | `logs/admin-auth.json` | 管理员密码哈希文件路径 |
| `BANNER_FILE` | `logs/banner.json` | 首页公告配置文件路径 |
| `ADMIN_SETUP_CODE` | 启动时随机生成 | 可选的首次初始化码；不设置时显示在服务端控制台 |
| `PEER_ICE_SERVERS` | Google STUN | PeerJS 使用的 ICE 服务器 JSON 数组，可配置 STUN/TURN |

## 日志

服务器会将日志实时格式化输出到控制台，同时以一行一条 JSON 的形式追加到 `logs/wordpk.log`。日志目录属于运行数据，不纳入 Git。

主要事件包括：

- `room_created`
- `match_started`
- `match_finished`
- `room_destroyed`
